# Core 2.2 Secondary Views Responsive Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port the approved Core Dashboard responsive/mobile-card behavior to Components, All Extensions and Updates, while validating Diagnostics and Information and correcting the canonical Core package identity.

**Architecture:** Reuse the existing public `xdecaro.admin` responsive-table stack contract instead of adding a second mobile system. Core-specific templates opt into `xdecaro-suite__responsive-wrap--stack`; Diagnostics and Information retain their existing shared card/definition layouts. Keep desktop table layouts unchanged.

**Tech Stack:** Joomla 6.1.3, PHP 8.3+, Web Asset Manager, shared Core CSS contract, container queries.

**Spec:** User-approved Dashboard behavior in PR #31 and the current conversation.

## Global Constraints

- Joomla 6.1.3 only.
- PHP 8.3 or newer.
- No merge or release until all views are manually accepted.
- Desktop tables remain unchanged.
- Narrow layouts must use readable stacked cards without horizontal overflow.
- Canonical package identity is `pkg_core`.

## Review Focus

- Components package details remain expandable after the outer row becomes a mobile card.
- Nested child-extension tables also stack on narrow layouts.
- All Extensions keeps element/type/version/state/package data readable without duplicate element noise.
- Updates keeps status and installer action readable on narrow layouts.
- Information never exposes the retired `pkg_xdecarocore` package identity.
