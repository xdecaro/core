# Core 2.2.0 Shared Admin UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Core 2.2.0 with a public, opt-in `xdecaro.admin` administrator UI layer that standardizes responsive page structure, forms, filters, accordions, KPI blocks and responsive tables across the xdecaro ecosystem without coupling consumer business logic to Core.

**Architecture:** Preserve the existing dependency chain and add one new public Web Asset layer: `xdecaro.core → xdecaro.components → xdecaro.admin`. Promote only domain-neutral `xdecaro-suite` rules from `com_xdecarocore` into the system plugin, keep Core-dashboard-specific selectors private, and make the Core component itself consume the same public asset through `AssetService::useAdminUi()`.

**Tech Stack:** Joomla 6.1.3 administrator, PHP 8.3+, Joomla Web Asset Manager, PHP contract tests, CSS/container queries, existing Core build/release scripts and GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-27-core-2.2.0-shared-admin-ui-design.md`

## Global Constraints

- Joomla: **6.1.3 only**.
- PHP: **8.3 or newer**.
- Core UI is opt-in; never inject the shared administrator asset globally.
- Shared rules must remain scoped to xdecaro wrappers and must not restyle Atum globally.
- Do not introduce page-wide `overflow-x: hidden` to mask defects.
- Preserve existing `xdecaro.core` and `xdecaro.components` public contracts.
- Keep product/domain behavior out of Core UI primitives.
- Core 2.2.0 must inherit the verified Core 2.1.0 canonical `pkg_core` migration; do not branch implementation from the current 2.0.1 `main` unless PR #26 has first been merged.
- Consumer migrations (People, Courses, Organizations, Membership, Competitions, Photos) are out of scope for this Core release; this release only makes the shared contract ready for them.

## Review Focus

- **Narrow content inside a wide browser:** with Atum sidebar/chrome leaving ~393 px effective content width, the suite must shrink without widening the whole administrator page; pin this in Task 3.
- **Long technical values:** UUIDs, hashes and backup filenames must wrap inside cards/tables instead of forcing page overflow; pin this in Task 3.
- **Joomla form controls on mobile:** standard `.control-group`, Choices/select/calendar/input markup inside `.xdecaro-form` must become a readable vertical flow at phone widths; pin this in Task 3.
- **Variable KPI counts:** four metrics must not inherit the old five-item "last card spans full row" behavior unless an explicit modifier is present; pin this in Task 3.
- **Responsive table accessibility:** stacked/card table mode must preserve column context through `data-label`, while tables without that contract remain safely scrollable inside their wrapper; pin this in Task 3.
